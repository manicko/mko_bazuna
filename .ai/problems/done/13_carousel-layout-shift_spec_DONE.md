## 1. Problem statement

On the ad-detail page the photo gallery ("carousel"/slider) **jumps** whenever the
user navigates between photos: switching to a photo that is taller or shorter than
the current one resizes the main-image area, which in turn shifts the thumbnail
strip and every block below it (ad description, price, features, contact button).

The root cause is in `src/backend/templates/ads/detail.html`:

- **L35** — wrapper `<div class="relative w-max mx-auto mb-4">`.
  `w-max` lets the wrapper shrink to the image's rendered height, so the wrapper
  height = image height.
- **L44** — `<img id="detail-main-image" class="max-h-96 max-w-lg object-contain bg-gray-100 rounded-lg" src="{{ primary.thumbnail_large_url|default:primary.image_url }}">`.
  `max-h-96` (384 px) + `max-w-lg` (512 px) + `object-contain` scale **each loaded
  image to fit within a 512×384 box while preserving that image's own aspect
  ratio**. Because the `src` is the per-image LARGE thumbnail (see §2), every swap
  changes the rendered height.

### Quantified proof of the jump (verified)

The LARGE thumbnail is generated by `src/backend/apps/media/services/thumbnails.py`
at the box **(1280, 960)** via `PIL.Image.thumbnail()` (preserves aspect ratio):

| Sample photo (natural) | LARGE thumb | Rendered main img (512×384 box, `object-contain`) | Rendered height |
|---|---|---|---|
| 2000×500 (4:1, very wide) | 1280×320 | 512×128 | **128 px** |
| 500×2000 (1:4, very tall) | 240×960 | 96×384 | **384 px** |
| 1280×960 (4:3) | 1280×960 | 512×384 | **384 px** |
| 1000×1000 (1:1) | 960×960 | 384×384 | **384 px** |

Height delta between a 4:1-wide photo and a 1:4-tall photo = **256 px** of vertical
shift per swap. The inline swap IIFE (`detail.html` L102–L112) sets
`img.src = t.dataset.thumbUrl` (the LARGE thumb URL, L89) on every thumb/arrow
click, so each navigation triggers the full height change.

> Note: the `width="1280" height="960"` HTML attrs on L46 do **not** stabilise the
> height — once an image is loaded, `object-contain` under `max-*` constraints uses
> the loaded image's **intrinsic** ratio (MDN: `aspect-ratio` for `<img>`), not the
> attribute ratio.

### User-visible symptom

Buyer is reading the ad → switches photo → the whole content below the image
visibly "jerks" up/down. This is a Cumulative-Layout-Shift (CLS) defect that breaks
the reading flow and, on mobile (image above text, `flex-col lg:flex-row`), is
especially disruptive.

## 3. Conceptual development tasks

Each task is independent and can be owned/planned separately.

### T1 — Pin the main-image container to a fixed aspect ratio (PRIMARY FIX)

- **Purpose:** Eliminate vertical layout shift by giving the main-image box a
  single, swap-invariant height while keeping `object-contain` (no crop).
- **Concrete change (`detail.html`):**
  - L35 wrapper: `relative w-max mx-auto mb-4`
    → `relative w-full max-w-lg aspect-[4/3] mx-auto mb-4`
  - L44 image: `max-h-96 max-w-lg object-contain bg-gray-100 rounded-lg`
    → `w-full h-full object-contain object-center bg-gray-100 rounded-lg`
- **Expected outcome:** Swapping between any two photos produces **0 px** of
  vertical shift (box height = `box-width × (4/3)`, invariant). Main image stays
  fully visible (letterboxed for non-4:3 photos). `object-contain` retained,
  `object-cover` absent → `test_gallery_markup.py` assertions pass unchanged.
- **Dependencies:** None (CSS-only). Requires a Tailwind rebuild (see T2).
- **Test impact:** None — all `test_gallery_markup.py` assertions remain valid
  (object-contain present, object-cover absent, ids/classes/anchors/href/src
  untouched). No-DB test (`test_detail_context.py`) unaffected.

### T2 — Regenerate Tailwind `output.css` with the new utilities

- **Purpose:** Ship the newly-referenced Tailwind utilities (`aspect-[4/3]`, and
  optionally `transition-opacity`/`duration-200` from T3) as compiled CSS so the
  fix actually takes effect.
- **Concrete change:**
  - **Dev:** restart the `web` container (`docker compose up -d`), or run
    `docker compose exec web tailwindcss -i src/theme/static/theme/css/input.css -o src/theme/static/theme/css/output.css --minify`
    (this exact command is already documented in `docker-compose.dev.override.yml` L5).
  - **Prod / CI:** rebuild the image so `docker/Dockerfile` L76
    (`tailwindcss -i … -o … --minify`) re-runs with the new classes scanned via
    `@source "src/backend/templates/**/*.html"` in `input.css`.
- **Expected outcome:** `output.css` ships `.aspect-\[4\/3\]{aspect-ratio:4/3}`
  (and any optional bonus classes).
- **Dependencies:** T1 (must be done first, so the new classes are in a template
  to be scanned).
- **Test impact:** None — tests assert on rendered HTML, not on compiled CSS.

### T3 — (OPTIONAL / ENHANCEMENT) Smooth cross-fade + hero preloading

- **Purpose:** Improve perceived smoothness (a fade between swaps) and LCP by
  eager-loading the hero image.
- **Concrete change:**
  - L42/44: add `fetchpriority="high"` and change `loading="lazy"` → `loading="eager"`
    on `#detail-main-image` (it is the initial hero image).
  - Add `transition-opacity duration-200` to the image and an `opacity-0`/`opacity-100`
    toggle inside the existing `update()` IIFE (L107) — ~3 lines of JS, additive.
- **Expected outcome:** Fade transition on swap; hero flagged high-priority for LCP.
- **Dependencies:** T1.
- **Priority:** Lower — the jump is fixed by T1 alone; this is polish + an SEO perf win.
- **Test impact:** None expected (no class/attr the tests assert on changes;
  `object-contain`/`object-cover` unaffected).

### T4 — (DEFERRED / FUTURE) Store natural image dimensions on `AdImage`

- **Purpose:** Capture `width`/`height` (pixels) on `AdImage` for richer
  layout options (accurate per-image aspect boxes, responsive `srcset`/`sizes`).
- **Concrete change:** two nullable `PositiveIntegerField`s on
  `apps/ads/models.py`::`AdImage` (L508) + a data migration backfilled from
  `PIL.Image.open(...).size` (tolerant of missing files on disk, per
  `media/services/thumbnails.py` patterns).
- **Expected outcome:** Per-image intrinsic dimensions available in templates.
- **Dependencies:** None (deferred).
- **Why NOT a fix for this bug:** forcing each image to its *own* natural ratio
  makes the container height vary per swap → **re-introduces the jump** (MDN:
  a bare `aspect-ratio` on `<img>` yields to the intrinsic ratio). T4 only helps
  if combined with a fixed fallback ratio (T1). Kept out of scope for this fix.

## 5. Research summary

A delegated Researcher agent investigated (read-only) the architecture and modern
web best practices. Findings (HIGH confidence throughout):

**Root cause (confirmed):** The jump is caused by `max-h-96 max-w-lg
object-contain` on the main `<img>` inside a `w-max` wrapper — the rendered
height equals the loaded image's natural height (constrained by the 512×384 box),
which varies by aspect ratio. Switching `src` to the per-image LARGE thumbnail
triggers the re-layout. Verified compiled Tailwind values: `max-h-96`=384 px,
`max-w-lg`=512 px.

**Modern best practices (MDN / web standards):**
- The canonical CLS-elimination pattern for a heterogeneous-ratio image switcher
  is a **fixed `aspect-ratio` container + `object-contain`** (MDN: "Image
  aspect-ratio: preventing jank"). `aspect-ratio` is Baseline (Sep 2021);
  `object-fit` is supported since 2016.
- A **fixed-pixel-height container + `object-contain`** is the equivalent
  alternative (stable height, no crop).
- **JS-measured natural dimensions + per-image dynamic `aspect-ratio` FAILS the
  no-jump requirement**: forcing each image to its *own* ratio makes the box
  height change per swap, reproducing the bug. It would only help combined with a
  fixed fallback ratio.

**Tailwind CSS v4 — verified against the repo's own `output.css`:**
- `aspect-video`, `aspect-square`, `object-contain`, `object-cover`,
  `object-center`, `bg-gray-100`, `rounded-lg`, `max-h-96`, `max-w-lg` are
  **already compiled** into `src/theme/static/theme/css/output.css`.
- `aspect-[4/3]` (arbitrary value), `transition-opacity`, `duration-200`,
  `scrollbar-gutter-stable` are **not yet compiled** → require a Tailwind rebuild
  (dev: auto on container restart / `docker compose exec web tailwindcss …`;
  prod/CI: image rebuild per `docker/Dockerfile` L76). New classes are picked up
  purely by being referenced in a template, because `input.css` declares
  `@source "src/backend/templates/**/*.html"`.

**Approaches evaluated (pros/cons vs. R1 no-crop & R2 no-jump):**

| Approach | No crop? | No jump? | Effort | DB/migration? |
|---|---|---|---|---|
| A — fixed aspect-ratio wrapper (`aspect-[4/3]`) + `object-contain` | Yes (letterbox) | Yes (height invariant) | CSS only | No |
| B — fixed-pixel-height wrapper (`h-96`) + `object-contain` | Yes (letterbox) | Yes (height invariant) | CSS only | No |
| C — per-image dynamic `aspect-ratio` (stored w/h) | Yes (letterbox) | **No** (re-introduces jump) | Migration + backfill + JS | Yes |

**Recommendation (tied to this architecture):** **Approach A** with
`aspect-[4/3]` — a pure-Tailwind change with **no Python/DB/JS-for-the-fix**
changes. It honours "production code > tests" (zero test distortion —
`test_gallery_markup.py` passes unchanged), fits the HTMX-MPA + minimal-inline-JS
convention, and is the MDN-recommended anti-jank pattern. `aspect-video` (16:9)
is a safe **no-rebuild** substitute if an immediate deployment cannot include a
CSS rebuild, at the cost of more letterboxing on portrait/square photos.

## 10. Out of scope

- Adopting a JS carousel library (Swiper/embla/GLightbox-as-carousel) — R4 forbids it.
- Per-image natural-dimension storage on `AdImage` (T4) — does **not** fix the jump;
  defer unless a richer responsive-image feature is otherwise required.
- Changing thumbnail rendering (`object-cover` → `object-contain` in the strip) —
  would break the uniform 44×44 touch-target grid and a `test_gallery_markup.py`
  assertion (L150–L158); not the reported problem.
- Responsive breakpoints for the gallery layout beyond the existing
  `flex-col lg:flex-row` (L30) — the fix is breakpoint-agnostic.
- i18n (`{% trans %}`) — unaffected; no user-visible strings change except the
  optional new `object-center` (CSS only).
