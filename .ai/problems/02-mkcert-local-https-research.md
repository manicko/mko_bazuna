## 1. How mkcert Works for Local Development

### Certificate Generation Process
mkcert is a zero-config command-line tool created by Filippo Valsorda that generates locally-trusted TLS certificates:

1. **Creates a Local Certificate Authority (CA)** on your machine
2. **Installs the CA into the system trust store** - on Windows, this is the Certificate Store; on macOS, Keychain; on Linux, the system CA bundle
3. **Generates certificates signed by this CA** - browsers and OS trust them because they trust the root CA

### Trust Chain
```
mkcert Root CA (rootCA.pem + rootCA-key.pem)
    └── Local Development Certificates (localhost.pem, myapp.local.pem, etc.)
            └── Trusted by browsers and OS because CA is installed
```

The CA files are stored at:
- **Windows:** `%LocalAppData%\mkcert\` or user's home directory
- **macOS/Linux:** `~/.local/share/mkcert/`

**Critical Security Note:** The `rootCA-key.pem` file is the private key of your local CA. Anyone with this key can generate certificates trusted by your machine. Never share or commit this file.

### Browser Compatibility
- **Chrome/Chromium:** Full trust when CA installed
- **Firefox:** Requires `libnss3-tools` (Linux) or works automatically (macOS/Windows) - mkcert handles this during `-install`
- **Safari:** Trusts via macOS Keychain
- **Edge:** Trusts via Windows Certificate Store

**Requirement:** mkcert automatically adds Subject Alternative Names (SANs) to certificates, which is required by modern browsers (Chrome 58+ rejects certs without SANs).

## 2. Use Cases Requiring Local HTTPS

### Features That Require Secure Context (HTTPS)

| Feature | Requirement | Notes |
|---------|-------------|-------|
| **Secure Cookies** | HTTPS only | `SESSION_COOKIE_SECURE=True` blocks cookies over HTTP |
| **OAuth Callbacks** | HTTPS required | Most OAuth providers (Google, GitHub, etc.) reject `http://` redirect URIs |
| **WebAuthn** | HTTPS required | Passwordless authentication, passkeys require secure context |
| **Service Workers** | HTTPS required | Won't register on HTTP (except localhost in some browsers) |
| **HTTP/2** | TLS required | Browsers only support HTTP/2 over HTTPS |
| **WebRTC** | HTTPS required | getUserMedia() and other WebRTC APIs require secure context |
| **Push Notifications** | HTTPS required | Web Push API requires secure context |
| **Geolocation API** | HTTPS required | Injected location spoofing works, but real devices need HTTPS |
| **Camera/Microphone Access** | HTTPS required | MediaDevices APIs require secure context |

### Django-Specific Considerations
The project's `base.py` enables these settings:
- `SESSION_COOKIE_SECURE = True` - blocks session cookies over HTTP
- `CSRF_COOKIE_SECURE = True` - blocks CSRF cookies over HTTP  
- `SECURE_SSL_REDIRECT = True` - redirects HTTP to HTTPS
- `SECURE_HSTS_SECONDS = 3600` - forces HTTPS for 1 hour
- `SECURE_PROXY_SSL_HEADER` configured for nginx reverse proxy

Current `dev.py` disables these, but this means you cannot test HTTPS-dependent features locally.

## 3. Integration with Docker/nginx

### Current Project Structure
The nginx configuration (`docker/nginx/nginx.conf`) already expects certificates at:
```nginx
ssl_certificate /etc/nginx/certs/fullchain.pem;
ssl_certificate_key /etc/nginx/certs/privkey.pem;
```

And `docker-compose.prod.yml` mounts them via:
```yaml
- ${TLS_CERT_PATH:-/etc/nginx/certs}:/etc/nginx/certs:ro
```

### mkcert Integration Approaches

#### Approach A: Volume Mount Certificates into nginx Container
```bash
# Generate certificates in project directory
mkdir -p docker/nginx/certs
cd docker/nginx/certs
mkcert localhost mkobazuna.local 127.0.0.1 ::1

# For nginx, combine mkcert's cert+key into fullchain.pem format
cat localhost.pem localhost-key.pem > fullchain.pem
```

Update `docker-compose.dev.override.yml`:
```yaml
nginx:
  profiles:
    - use-nginx
  volumes:
    - ./docker/nginx/certs:/etc/nginx/certs:ro
```

Then run:
```bash
docker-compose -f docker-compose.yml -f docker-compose.dev.override.yml --profile use-nginx up
```

#### Approach B: Generate Inside a Container (mkcert-docker)
Use a container to generate and serve certificates:
```yaml
certgen:
  image: stephenlb/mkcert
  volumes:
    - ./docker/nginx/certs:/certs
  command: >
    sh -c "mkcert -install && mkcert -cert-file /certs/fullchain.pem 
    -key-file /certs/privkey.pem localhost"
```

#### Approach C: Use HTTPS Development with Django Directly
For development without nginx:
```bash
# Install mkcert on host, generate certs
mkcert localhost

# Configure Django for HTTPS in dev (override SECURE_PROXY_SSL_HEADER)
# In dev.py, add:
SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")
```

### Key Files Generated by mkcert
```
localhost.pem          # Certificate (public key + metadata)
localhost-key.pem      # Private key
rootCA.pem             # CA certificate (can be shared with team)
rootCA-key.pem         # CA private key (NEVER share/committed)
```

For nginx, rename files:
```bash
mkcert localhost
cp localhost.pem fullchain.pem
cat localhost-key.pem >> fullchain.pem  # or use as privkey.pem
```

## 4. Setup Complexity vs Benefit for This Django Project

### Complexity Analysis

| Task | Effort | Notes |
|------|--------|-------|
| Install mkcert | Low (5 min) | `choco install mkcert` on Windows |
| Install CA (`mkcert -install`) | Low (one-time) | Requires admin privileges on Windows |
| Generate certificates | Low (1 min) | `mkcert localhost` |
| Mount into Docker | Medium | Requires updating compose override |
| Team onboarding | Low-Medium | Each developer runs `mkcert -install` once |
| Certificate renewal | Low | Run `mkcert localhost` again (valid ~2 years) |

### Benefits for Mko Bazuna

**Immediate Benefits:**
- Test OAuth flows locally (Telegram bot webhook callbacks, if implemented)
- Test secure cookies and session behavior identical to production
- Test HTTP/2 performance in development
- Test HSTS header behavior
- No need to modify `base.py` security settings

**Future-Proofing:**
- If WebAuthn or other HTTPS-only features are added, work immediately
- Matches production environment (no "works in dev, breaks in prod" issues)
- Service worker support if PWA features are added

### Risks and Drawbacks

| Risk | Severity | Mitigation |
|------|----------|------------|
| `rootCA-key.pem` exposure | Critical | Never commit to repo, add to `.gitignore` |
| Team onboarding friction | Low | Document `mkcert -install` in README |
| Certificate expiration (2 years) | Low | Renew by running `mkcert localhost` again |
| Browser trust issues | Low | Restart browser after CA install, clear cache |

## 5. Certificate Renewal and Maintenance

### Expiration Timeline
- mkcert certificates are valid for **2 years and 3 months** (hardcoded in source)
- This is intentionally under 825 days to comply with macOS/iOS limits
- The CA itself does not expire - only issued certificates

### Renewal Process
```bash
# Simply re-run the generation command
mkcert localhost 127.0.0.1 ::1 myapp.local

# The new certificate overwrites the old one
# No need to re-run mkcert -install (CA already trusted)
```

### Automation Options
```bash
# Add to package.json scripts or Makefile
"scripts": {
  "dev:certs": "mkcert -install && mkcert localhost 127.0.0.1 ::1 mkobazuna.local"
}

# Or as a setup script
#!/bin/bash
# scripts/setup-local-https.sh
mkdir -p docker/nginx/certs
mkcert -install
cd docker/nginx/certs
mkcert localhost 127.0.0.1 ::1 mkobazuna.local
echo "*.pem" >> ../../.gitignore.local
```

### Verification Commands
```bash
# Check CA location
mkcert -CAROOT

# Inspect certificate details
mkcert -inspect localhost.pem

# Clean expired certs from cache
mkcert -clean

# Uninstall CA (if compromised)
mkcert -uninstall
```

### .gitignore Recommendations
```gitignore
# mkcert certificates (if not shared with team)
docker/nginx/certs/*.pem
!docker/nginx/certs/.gitkeep

# Or if sharing certificates but not CA key
docker/nginx/certs/*-key.pem

# CA should NEVER be in repo
*.local/share/mkcert/
```

## 6. Decision Matrix: Disable HTTPS vs Use mkcert

| Criterion | Disable HTTPS | Use mkcert |
|-----------|--------------|------------|
| **Setup effort** | Low (already done) | Low-Medium |
| **Feature testing** | Limited (no HTTPS features) | Full (all HTTPS features work) |
| **Production parity** | Poor (different cookie behavior) | Excellent (identical to prod) |
| **Team coordination** | None | Each dev runs `mkcert -install` once |
| **Maintenance** | None | Renew every ~2 years |
| **Security realism** | Poor | Excellent |

### Recommendation
Given the project already uses nginx with TLS configuration and has security-hardened defaults in `base.py`, **mkcert is the preferred approach** because:

1. The nginx config already references `/etc/nginx/certs/fullchain.pem` - designed for TLS
2. `SECURE_SSL_REDIRECT = True` and `SESSION_COOKIE_SECURE = True` are production-ready defaults
3. OAuth callbacks (for Telegram bot webhooks or future integrations) require HTTPS
4. Minimal ongoing maintenance (2-year renewal cycle)
5. Future-proofs the project for WebAuthn, Service Workers, HTTP/2 testing

## 7. Implementation Steps (Option 2)

If choosing mkcert for development:

1. **Install mkcert on each development machine:**
   ```bash
   # Windows
   choco install mkcert
   
   # Or Scoop
   scoop install mkcert
   ```

2. **Install the local CA:**
   ```bash
   mkcert -install
   ```

3. **Generate certificates in project:**
   ```bash
   mkdir -p docker/nginx/certs
   cd docker/nginx/certs
   mkcert localhost 127.0.0.1 ::1 mkobazuna.local
   # Rename for nginx compatibility
   cp localhost.pem fullchain.pem
   cp localhost-key.pem privkey.pem
   ```

4. **Update docker-compose.dev.override.yml:**
   ```yaml
   nginx:
     profiles:
       - use-nginx
     volumes:
       - ./docker/nginx/certs:/etc/nginx/certs:ro
   ```

5. **Update dev.py to support HTTPS (optional):**
   ```python
   # If testing directly with Django runserver
   SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")
   USE_X_FORWARDED_HOST = True
   ```

6. **Add to README.md:**
   ```markdown
   ## Local HTTPS Development
   
   Install mkcert and run once per machine:
   ```bash
   mkcert -install
   mkdir -p docker/nginx/certs
   cd docker/nginx/certs
   mkcert localhost 127.0.0.1 ::1 mkobazuna.local
   cp localhost.pem fullchain.pem
   cp localhost-key.pem privkey.pem
   ```
   
   Then run with nginx profile:
   ```bash
   docker-compose --profile use-nginx up
   ```
   ```
