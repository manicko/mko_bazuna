# TS-XXX. Архитектура категорий и справочников объявлений

**Статус:** Approved

---

# 1. Цель

Построить масштабируемую архитектуру объявлений, в которой:

* дерево категорий остается компактным и стабильным;
* новые варианты публикации и характеристики добавляются без изменения кода;
* поиск и фильтрация работают по индексируемым связям PostgreSQL;
* все изменяемые данные управляются через административную панель;
* архитектура подходит для дальнейшего расширения проекта.

---

# 2. Основные принципы

Категория отвечает только на вопрос:

> **Что является объектом объявления?**

Все остальные параметры являются справочниками и не входят в дерево категорий.

Запрещается создавать категории вида:

```
Квартиры → Продажа
Квартиры → Аренда
Квартиры → Посуточно
```

или

```
Телефоны → Новые
Телефоны → Б/У
```

Такие данные должны храниться в справочниках.

---

# 3. Категории (Category)

Категории представляют собой дерево (MPTT) и являются основой навигации сайта.

## Пример

```
Недвижимость
├── Квартиры
├── Дома
├── Комнаты
├── Гаражи
└── Земельные участки

Товары
├── Телефоны
├── Велосипеды
└── Ноутбуки

Услуги
├── Репетиторы
├── Ремонт
└── Уборка
```

Категория никогда не содержит:

* цель публикации;
* характеристики объявления;
* состояние товара;
* бизнес-логику.

---

# 4. Универсальная система справочников

Все изменяемые значения проекта хранятся в единой системе справочников.

Используются две модели.

## LookupGroup

Группа справочника.

Примеры:

```
listing_purpose
listing_feature
currency
condition
fuel_type
building_type
```

---

## LookupItem

Элемент справочника.

Структура:

```
id
group_id
code
slug
sort_order
is_active
translations
icon (optional)
color (optional)
```

Все значения управляются через административную панель.

Добавление новых элементов не требует изменения кода.

---

# 5. ListingPurpose

ListingPurpose представляет собой группу справочника (`LookupGroup`).

Определяет:

> **Что пользователь хочет сделать с объектом?**

Каждое объявление имеет только одну цель публикации.

Одна категория может поддерживать множество целей.

## Примеры

### Квартиры

* Продажа
* Долгосрочная аренда
* Посуточная аренда

### Велосипеды

* Продажа
* Прокат

### Репетиторы

* Предлагаю обучение
* Ищу преподавателя

Связи:

```
Category ←→ LookupItem (group = listing_purpose)

Ad → LookupItem (group = listing_purpose)
```

---

# 6. ListingFeature

ListingFeature представляет собой группу справочника (`LookupGroup`).

Используется для описания дополнительных характеристик объявления.

Одно объявление может иметь любое количество характеристик.

Каждая категория самостоятельно определяет допустимый набор характеристик.

## Примеры

### Квартиры

* Новостройка
* Вторичный рынок
* Апартаменты
* Пентхаус
* Вид на море
* Без посредников

### Велосипеды

* Новый
* Б/У
* Электровелосипед

### Репетиторы

* Онлайн
* Очно
* Частный преподаватель
* Выезд на дом

Связи:

```
Category ←→ LookupItem (group = listing_feature)

Ad ←→ LookupItem (group = listing_feature)
```

---

# 7. Создание нескольких объявлений

Каждое объявление представляет одно коммерческое предложение.

Если пользователь хочет:

* продать квартиру;
* сдавать квартиру долгосрочно;
* сдавать квартиру посуточно,

создаются три отдельных объявления.

Причины:

* разные цены;
* разные условия;
* разные описания;
* разные фотографии (при необходимости);
* разные правила публикации;
* максимально простой поиск;
* максимально простая бизнес-логика.

---

# 8. Копирование объявления

Для ускорения публикации реализуется функция:

> **Создать объявление на основе существующего**

При копировании автоматически переносятся:

* категория;
* описание;
* адрес;
* координаты;
* фотографии;
* характеристики (ListingFeature);
* контакты;
* остальные общие поля.

Пользователь изменяет только:

* ListingPurpose;
* цену;
* условия;
* описание (при необходимости).

Таким образом создание второго объявления занимает несколько секунд.

---

# 9. Повторное использование фотографий

Все изображения проходят проверку на дублирование.

При загрузке файла вычисляется криптографический хеш (SHA-256).

Если файл уже существует:

* повторная загрузка не выполняется;
* создается новая связь объявления с существующим изображением.

Если файл отсутствует:

* изображение сохраняется;
* создается новая запись.

В результате:

* одинаковые изображения физически хранятся один раз;
* несколько объявлений могут использовать один и тот же файл;
* экономится место на диске;
* отсутствует дублирование файлов.

# 10. Архитектура связей

```
                   Category
                      │
          ┌───────────┴───────────┐
          │                       │
          ▼                       ▼
 LookupItem                  LookupItem
(group=list. purpose)    (group=list. feature)
          ▲                       ▲
          │                       │
          │                       │
          └──────── Ad ───────────┘
```

---

# 11. Структура связей

```
Category
    ↔ LookupItem (ListingPurpose)

Category
    ↔ LookupItem (ListingFeature)

Ad
    → Category

Ad
    → LookupItem (ListingPurpose)

Ad
    ↔ LookupItem (ListingFeature)
```

---

# 12. Производительность

Используются только стандартные механизмы PostgreSQL:

* ForeignKey
* ManyToMany
* B-Tree индексы

Использование EAV в MVP запрещено.

Все справочники кэшируются.

Все фильтры работают по индексируемым полям.

---

# 13. Администрирование

Администратор может:

* создавать группы справочников;
* создавать элементы справочников;
* изменять переводы;
* менять порядок отображения;
* отключать элементы;
* связывать элементы с категориями;
* использовать существующие элементы в новых категориях.

Новые значения начинают использоваться системой без выпуска новой версии приложения.

---

# 14. Итоговая модель

```
                     LookupGroup
                          │
                          │ 1:N
                          ▼
                     LookupItem
                     /        \
                    /          \
          (ListingPurpose)  (ListingFeature)
                  ▲               ▲
                  │               │
        M:N       │               │       M:N
      Category────┘               └────Category
                  ▲               ▲
                  │               │
                  │ FK            │ M:N
                  │               │
                  └────── Ad ─────┘
```

Данная архитектура является базовой архитектурой проекта и используется для всех разделов сайта (товары, услуги, недвижимость) без создания специализированных моделей под каждую предметную область.
