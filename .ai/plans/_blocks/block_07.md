# Block 7: URL State, Pagination & Navigation

## 1. Block Summary

Verifies that HTMX-driven navigation preserves the full active filter/sort/query parameter set in the browser URL (via `hx-push-url="true"`), that pagination behaves correctly across both the listings (`/`, `/category/<slug>/`, `/city/<slug>/`) and search (`/search/?q=`) surfaces, and that deep-linking and Back/Forward restoration work after fragment swaps. Locks in bug **B7**: the `lang=` parameter is omitted from all 9 pagination/chip/clear-all links in `ad_list.html`, degrading URL-share correctness across language switches.

## 3. Priority

**Medium.** Block 7 is the URL-state and navigation correctness layer that every other block's output (filter params, sort, FTS results) flows through — but it contains only **one confirmed bug (B7)**, which the verification doc explicitly rates as "a minor inconsistency — not a functional break" (`01_search_patterns_verification.md:450-452`): the page renders correctly in the active language via cookie/session; B7 only affects *shared/copy-pasted* paginated URLs (language re-detection from `Accept-Language`).

- **V6 (B7) is the single confirmed defect** — template fix + i18n consistency test. MEDIUM because it is a confirmed bug touching all 9 shared links (coordination surface), though LOW functional severity.
- **V4 (listings page-param validation) is MEDIUM** — full parity gap with the search view (`test_search_view.py:279-377` exists for `/search/` but not `/`); `Paginator.get_page()` is safe but entirely untested on the primary listings surface.
- **V8 (pagination URL-content) and V9 (deep-linking) are MEDIUM** — param preservation and deep-link correctness are the core user-facing contract of "URL state"; currently only a count is asserted.
- **V10 (Playwright Back/Forward) is MEDIUM** — browser-history restoration is user-visible and HTMX-specific; verified only manually.
- **V1, V2, V3, V5, V7 are LOW** — V1/V3/V5 are sufficiently covered; V2/V7 are cosmetic/consistency deviations with no user-facing risk.

No HIGH items: the HTMX branching (V1) and the 9-link count invariant (V5) are locked in; B7 is the only defect and it is non-functional.

## 5. Validator Recommendations

HTML attributes (`hx-get`, `hx-push-url`, `hx-target`, `hx-swap`) are unchanged in HTMX 2.0, and the 9-count invariant (`count("hx-get=") == 9`) is preserved under both the B7 lang fix and the migration. The `htmx:afterSwap` event at `header_catalog.html:544` needs NO rename — `addEventListener` fires both camelCase and kebab-case forms natively in HTMX 2.0. Block 7 assertions target `href`/`hx-get` URL *content* (e.g. `&lang=en`), not the `<script>` version tag, so the tag bump does not affect V5/V6/V8. The B6 code fix (`htmx.get` → `htmx.ajax`) at `header_catalog.html:536` is a header-level concern outside Block 7 scope.
