# Block 9: Language Switching & Per-Language FTS

## Block Summary

This block covers the language-switching infrastructure (`?lang=` priority, `lang_pref` cookie + session persistence, `SameSite`/consent-compliance gaps), the language-toggle template that drops active query params on switch, and the per-language FTS wiring that selects the correct `search_vector_{ru/bs/en}` column + PostgreSQL `text_search_config` at `/search/`. All per-language code paths are implemented and unit/integration-tested; two compliance gaps (cookie `SameSite` attribute, unconditional session write on `?lang=`) and one behavioral deviation (language toggle replaces the entire query string) remain open.

**Source:** `.ai/research/search-journeys-our-architecture.md:146`, `.ai/research/search-journeys-spec.md:218`, `.ai/problems/01_search_patterns_verification.md:196-206`, `.ai/problems/01_search_patterns_test_verification_top_plan.md:193-206`
**Top plan:** `.ai/problems/01_search_patterns_test_verification_top_plan.md` — Block 9 (G12), lines 193–206
**Deviation note:** The top plan's variation list (line 200) denotes per-language FTS as `/?lang=bs&q=<term>`, but FTS lives at `/search/` (`search/urls.py:12`, `search.py:33`). All test assertions for V1 must use `/search/?lang=<code>&q=<term>`, not `/`.

## Priority: **MEDIUM**

V1 and V2 are LOW risk — per-language FTS is fully implemented (`search.py:158-182`, `core/enums.py:222-237`) and locked by 39 unit+integration tests across `test_search_triggers.py`, `test_language_middleware.py`, and `test_language_end_to_end.py`. Both the vector selection and the language-priority chain are verified end-to-end.

V4 (DEVIATION) is the highest-risk item in this block: a buyer searching in Bosnian with active filters who clicks "EN" loses the entire query and filter state, landing on `/search/?lang=en` with no results context. This is a user-facing behavioral regression — the verification report (`01_search_patterns_verification.md:204`) claims "Language toggle preserves params ✅ Working" but that manual check likely used a bare URL without query params. The root cause is a single template line (`language_switcher.html:40`) replacing the query string.

V3 (2 gaps) is MEDIUM risk: Gap B (session write without consent gate at `language.py:118`) is an ePrivacy/GDPR compliance risk — `consent_preferences=false` should prevent the server from persisting a preferences cookie or session key, yet the middleware writes `django_language` unconditionally. Gap A (`samesite` not set at `language.py:87-91`) is a consistency/defense-in-depth issue — Django's default is `None` (browser → Lax), so it works in practice but diverges from the explicit `SameSite=Lax` pattern in `language_switcher.html:74` and `consent.py:70`.

V5 (process gap) is MEDIUM risk: no runtime defect exists today, but the absence of an extraction-freshness gate means future `{% trans %}` additions can silently produce untranslated msgid text in production with no CI signal — a gradual i18n-degradation vector.
