# Block 3: Search Submission & FTS Results

## Block Summary

Verifies the full-page header search submission flow: the header form carries only `q` (context-drop), the PostgreSQL FTS query executes against the per-locale search vector, results are ordered by `-rank, -published_at, -id`, single-word queries trigger fuzzy category subtree detection, and side effects (`SEARCH_PERFORMED` analytics, popular search increment, search history recording) fire on non-empty queries. Also covers the known gap where `sort=` is parsed but silently ignored in the FTS branch.

## Validator Recommendations

### FTS vector test setup
- The search vectors (`search_vector_ru`, `search_vector_bs`, `search_vector_en`) are populated by a **database trigger** (`ads_search_vector_update` → `ads_search_vector_fn`, migration `0007_search_vector_i18n`). The existing `create_test_ad` fixture in `src/backend/conftest.py:105-211` creates `Ad` rows via the ORM, which triggers the DB function — so FTS vectors are populated automatically in the Docker test DB. No manual `update_search_vector` call is needed.
- For **locale-specific** tests, use `?lang=bs` or `?lang=en` to activate the corresponding vector. The default `LANGUAGE_CODE` is `ru` (`search.py:162`), so unmarked requests hit `search_vector_ru`.
- Test ads must have titles/descriptions in the **target language** (Russian, Bosnian, or English) to match the locale's vector. English translations are stored in `title_en`/`description_en` fields (see migration `0007` and `ads/models.py:210-268`).

### Rank-ordering assertion approach
- **Rank-primary assertion (variation 2a):** Create two ads in the same category where one has a higher FTS relevance score (e.g., the query term appears in both title and description for ad A, but only in description for ad B). Since `SearchRank` weights `title` higher (`setweight(..., 'A')` vs `'B'` in the trigger SQL), ad A should outrank ad B even if ad B is newer. Assert `ids.index(ad_A.id) < ids.index(ad_B.id)`.
- **Published-at tiebreak assertion (variation 2b):** Already covered by `test_catalog_filters.py:447-475` — same-title ads with different `published_at`; newer appears first.
- **ID tiebreak assertion (variation 2c):** Create two ads with **identical** title, description, category, `published_at` (same timestamp) — they should have equal `rank` and equal `published_at`. Assert the one with the **higher `id`** (created later) appears first, verifying the `-id` final tiebreak.
- **Hidden-sort gap assertion (variation 6):** Create ads with widely varying `price_normalized_eur` values and a query that matches all. Request `/search/?q=<term>&sort=price_desc` and assert the result order matches FTS rank order (not price order). If rank ordering already places them by price coincidentally, use a tiebreaker ad (high price, lower rank) to prove rank wins.

### Analytics event assertion (variation 5)
- Import `from apps.analytics.models import AnalyticsEvent`. Assert `AnalyticsEvent.objects.filter(event_type="search_performed").count()` increments by exactly 1 after a non-empty `q` request. For authenticated users, assert `event.user_id == user.id`; for anonymous, assert `event.user_id is None`. Verify no event when `GET /search/` (empty query).
